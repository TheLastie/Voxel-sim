## Дополнительный аудит compaction

После закрытия основной задачи добавил в `src/scene.rs` более строгую
регрессию boundary compaction. Она задаёт разным выжившим REV уникальные
rest/previous positions, внешние силы и ускорения, частичные axis constraints,
ориентации и thermal conductivity, затем проверяет точную переиндексацию
значений. Отдельный тест сначала заполняет collision broadphase контактом
(1, 2), удаляет REV с индексом 0 и подтверждает новый корректный контакт (0, 1)
без индексов вне диапазона.

Проверки на текущем общем дереве: `VOXEL_SOLVER_BACKEND=cpu cargo test
--no-default-features` завершился успешно (74 library, 5 physics smoke, 1
contact-energy, 1 preconditioner, 3 fatigue-topology и 6 support tests; всего 90
тестов). `VOXEL_SOLVER_BACKEND=cpu cargo check --release --no-default-features
--all-targets`, `cargo fmt --all -- --check` и `git diff --check` тоже прошли.
В ходе первого запуска встретил незавершённую компиляционную правку PCG в
`src/solver.rs`; сообщил об этом Агенту 1 через `chat.md`, файл сам не правил,
после его исправления полный набор проверок прошёл.

К этому аудиту добавлен ещё один сценарий: узкая world-bound область удаляет
трёх внутренних REV обходного пути, оставляя два концевых REV. До удаления они
связаны одной цепью, после удаления cluster labels дают две отдельные компоненты.
Отдельный regression прошёл, затем полный результат обновлён: 75 library + 16
integration/binary tests, всего 91/91.

## Температурная зависимость вязкости жидкости

В движке появился настраиваемый Arrhenius-закон для вязкости жидкой фазы. API
`Scene::set_material_viscosity_temperature_model` принимает опорную температуру
(K) и молярную энергию активации (J/mol); референсное значение
`dynamic_viscosity_pa_s` остаётся неизменным. Contact viscosity использует
температуру каждого жидкого REV. Нулевое `Ea` сохраняет старое постоянное
поведение, встроенные материалы по умолчанию не получают неподтверждённую
калибровку. Единицы и ограничения описаны в `MATERIALS.md`.

Физический CPU capture `validation/liquid-viscosity-temperature.csv`: два водяных
REV при 333.15 K, `μref=1.002e-3 Pa·s` при 293.15 K, `Ea=17,000 J/mol`,
`dt=10 ms`, 2 подшага, 1,760 шагов/177 настоящих состояний/17.6 s. Получено
`μ=4.336900e-4 Pa·s`, скорость касательного сдвига
`1.00000e-3 → 9.5665e-4 m/s`, viscous heat `2.120421882e-11 J`, энергетическая
ошибка `1.111e-13 J`, импульсная ошибка 0, масса `0.002 kg`. Оба REV жидкие;
исходная связь разрушена при плавлении, в конце две компоненты. Значение `Ea`
демонстрационное и не калибровано для воды. GIF/MP4: 1120×700, 177 кадров,
10 fps/17.7 s; selector `:8840` отдал актуальные CSV/GIF/MP4 с HTTP 200.

Ограничения: объёмное течение, гидростатическое давление, свободная поверхность,
термозависимость, основанная на экспериментальной калибровке, и повторное
затвердевание пока отсутствуют. Главный viewer `:8765` не трогал: он уже служил
другой физический capture; запустил отдельный selector на `:8840`.

Валидация после температурной модели: CPU `cargo test --no-default-features`
PASS 94/94 (78 library + 16 integration/binary); release all-target check,
`cargo fmt --check`, renderer `py_compile`, JSON каталога, `git diff --check` и
полное декодирование GIF/MP4 прошли. Оба файла содержат 177 кадров 1120×700,
10 fps/17.7 s. Текущий selector `:8840` вернул статус, CSV, GIF и MP4 с HTTP
200; основной `:8765` продолжает отдавать прежний capture.

## Проверка сопутствующей оптимизации broadphase

В незакоммиченном общем diff обнаружил и воспроизвёл пропуск контактов между
fixed/dynamic REV, если индекс fixed REV меньше. Причина была в том, что после
сортировки пары lower-bin индексы читались по отсортированным значениям из
разных static/dynamic массивов. Исправил чтение по исходным endpoint-классам,
сортируя только итоговую пару, и убрал неиспользуемый локальный массив. Новый
regression проверяет обе перестановки индексов на удалённых ячейках: до fix он
падал, после fix проходит.

После коррекции весь CPU suite на общем дереве прошёл 97/97 (81 library + 16
integration/binary); `cargo check --release --no-default-features --all-targets`,
`cargo fmt --all -- --check`, renderer syntax, catalog JSON и `git diff --check`
тоже PASS. Поскольку исправление затрагивает оптимизацию Agent 1, его matched
support performance profile следует повторить до финального вывода о скорости.

### Дополнение: переиспользование broadphase scratch

Перенёс массив нижних bin-координат динамических REV из локальной временной
аллокации в `CollisionScratch`, который переиспользуется между проходами
broadphase. Это удаляет одну аллокацию на каждый вызов candidate builder; замер
времени ещё не выполнен. После изменения снова прошли все 97 CPU-тестов,
release all-target check, fmt check, renderer/catalog validation и
`git diff --check`. Численный эффект по времени шага нужно подтвердить matched
profile на той же сцене.

## Жидкость у твёрдой поверхности

Расширил contact viscosity на интерфейс жидкость–твёрдое тело: импульс
использует `μ(T)` жидкого REV и действует равными противоположными векторами
на оба свободных тела. Для contact жидкости с жидкостью сохраняется прежнее
гармоническое среднее. Regression проверяет снижение скорости обеих сторон,
импульс и полный энергетический бюджет.

Физический CPU capture `validation/liquid-solid-viscosity.csv`: вода + свободный
железный REV при 333.15 K, `μref=1.002e-3 Pa·s` при 293.15 K, демонстрационное
`Ea=17,000 J/mol`, 1,760 шагов, `dt=10 ms`, 2 подшага, 177 настоящих состояний
за 17.6 s. Скорость сдвига `5.0000e-4 → 4.7609e-4 m/s`, вязкое тепло
`1.035387246e-11 J`, energy error `5.553e-14 J`, momentum error
`5.684e-14 kg·m/s`, масса `0.008869999 kg`; одна связь разрушена плавлением,
две компоненты. GIF/MP4 содержат 177 кадров, 1120×700, 10 fps/17.7 s. Viewer
`:8841` отдаёт актуальные CSV/GIF/MP4 с HTTP 200; `:8765` не изменён.

Это частичный шаг к жидкости у стенок: свободная поверхность, pressure и
объёмный поток не реализованы; `Ea` не является калиброванной зависимостью воды.

Валидация после liquid–solid расширения: CPU suite 98/98 (82 library + 16
integration/binary), release all-target check, `cargo fmt --check`, renderer
`py_compile`, JSON catalog, `git diff --check` и полное ffmpeg декодирование GIF
и MP4 прошли. Новый capture остаётся доступен через selector `:8841` с HTTP 200;
основной viewer `:8765` не изменён.
