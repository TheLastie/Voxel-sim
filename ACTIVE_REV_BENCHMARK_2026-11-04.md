# Контрольный замер 332 750 активных REV — 4 ноября 2026

Цель остаётся: **300–400 тысяч активных REV, 10 мс физического времени за
не более 5 мс полного расчёта**, 60 FPS без накопления отставания, ошибка
физического отклика не более 10% и отсутствие численного источника энергии.
Эта цель пока не достигнута. FPS интерфейса сам по себе её не доказывает.

## Нагрузка и воспроизведение

Обычная редактируемая `.vxscene`: два железных куба по 55³ сантиметровых
REV, всего 332 750. Поверхности исходно касаются, скорости ±0,01 м/с,
температура исходного материала, гравитация и атмосферное давление нулевые,
шаг 10 мс с четырьмя механическими подшагами. Автоматическое укрупнение
отключено. Первый шаг содержит 3470 контактных наблюдений; последующие
шаги этого конкретного удара уже не имеют контактов. Они не заменяют
проверку длительного плотного контакта.

Создание и запуск внутри редактора из корня проекта:

```powershell
target/release/voxel-editor.exe --create-impact-scene validation/live-tests/active-332750.vxscene --side 55 --impact-gap-m 0 --impact-speed-m-s 0.01 --impact-dt-ms 10 --impact-substeps 4 --disable-auto-aggregation --profile-steps --run-scene
```

Повторное открытие сохранённого исходного состояния:

```powershell
target/release/voxel-editor.exe --scene validation/live-tests/active-332750.vxscene --disable-auto-aggregation --profile-steps --run-scene
```

Параметры проверяются до записи файлов. Создаётся общий настоящий `.vxm`
и два экземпляра в `.vxscene`; прежние каталоги ресурсов не перезаписываются.
Большой генерируемый ресурс и журналы находятся в игнорируемом
`validation/live-tests`, исходный генератор — в `src/scene_presets.rs`.

## Параллельный оператор связей при контакте

Вместо последовательного рассеивания сил по концам связей строки оператора
собираются независимо через уже имеющийся список инцидентных связей.
Разности и накопление остаются в f64; порядок сложения вкладов каждой
строки сохраняется. Контактные ограничения и точность PCG не ослабляются.
Для сравнения прежнего оператора перед запуском процесса установить
`$env:VOXEL_CONTACT_OPERATOR_ROWS='0'`; новый вариант включён по умолчанию
только выше существующего порога параллельной обработки.

Машина: Intel Core i5-14450HX, 10 ядер / 16 потоков,
NVIDIA GeForce RTX 5060 Laptop GPU, 16 ГБ RAM. Сборка release.
Замеры получены через рабочий MCP от штатного окна редактора,
автоматическая агрегация выключена в обоих запусках.

| Этап первого контактного шага | Последовательный оператор, мс | Параллельная сборка строк, мс |
| --- | ---: | ---: |
| Весь шаг решателя, 10 мс симуляции | 175 452,17 | 102 810,81 |
| Механическая система, включая вложенные этапы | 165 076,80 | 94 034,85 |
| └ сборка системы | 5 133,26 | 5 262,46 |
| └ факторизация | 916,88 | 916,48 |
| └ PCG | 152 893,96 | 81 728,56 |
| Число итераций PCG суммарно | 3691 | 3691 |
| Относительная невязка | 6,5959325e−6 | 6,5959325e−6 |

Один парный запуск: ускорение полного первого шага **1,71×**, PCG **1,87×**.
Это измерение, не статистическая гарантия. Следующие семь шагов практически
не ускорились: контактов уже нет, и новый контактный оператор там не работает.
Порядка 7–8 секунд на обычный последующий шаг тоже далеко от бюджета 5 мс.
Вложенные этапы нельзя ещё раз складывать с родительскими строками.

В восьми совпадающих моментах времени 0,01–0,08 с точно совпали число
итераций, невязка, энергетический журнал, топология и опубликованная
выборка состояния. Выборка не является полным сравнением всех 332 750 REV.
Дополнительно четыре модульные проверки оператора покрывают смешанные
маски осей, неактивный конец связи, нулевой вектор, большое общее смещение,
пустые строки и прохождение большого массива через рабочий порог.

Исходные свидетельства: `validation/live-tests/active-baseline-mcp.json`,
`contact-rows-native.jsonl`, `contact-rows-comparison.json`,
`active-baseline.png`, `contact-rows-native.png`.

## Параллельное вычисление энергии связей

Два учёта энергии вычисляют независимые значения связей параллельно,
затем распределяют их по REV и суммируют в прежнем последовательном
порядке. До- и послешаговые значения не переиспользуются между разными
состояниями. Буфер сохраняет выделенную память между вызовами; все
читаемые значения каждый раз пересчитываются. Порог одинаков для обоих
проходов — 8192 REV. Переменная `VOXEL_ENERGY_EDGES_PARALLEL=0`
оставляет вычисление энергий последовательным для сравнений.

Две проверки подтвердили побитовое совпадение энергетических бюджетов,
нодального тепла и сумм при смешанных закреплениях, удалённой связи,
разных температурах, поворотах и анизотропии, а также повторном использовании
буфера другого размера. Общий свежий прогон: **270 проверок прошли**
(228 библиотечных, 28 editor, 3 MCP и 11 физических); один ручной
бенчмарк сборщика метрик штатно пропущен. Release-editor собран.
Журналы: `validation/live-tests/active-optimization-regression.log`
и `energy-edges-release-build.log`. `git diff --check` проходит;
прохождение полного форматирования проекта не подтверждено.

Повторный запуск той же сцены с обеими оптимизациями:

| Измерение | Исходный вариант, мс | Обе оптимизации, мс |
| --- | ---: | ---: |
| Первый контактный шаг решателя | 175 452,17 | 100 565,94 |
| Медиана шести совпадающих бесконтактных шагов 0,03–0,08 с | 7 406,65 | 3 880,18 |

Первый удар ускорился в **1,74×**, последующие указанные шаги — в **1,91×**.
На первом шаге начальный энергетический проход занял 255,95 мс,
послешаговый — 329,23 мс. В запуске только с параллельным контактным
оператором они занимали 2505,64 и 1882,03 мс соответственно. Ускорение
этих проходов нельзя выдавать за ускорение всего решателя.

Все восемь сопоставимых опубликованных состояний, энергетические журналы,
топология, итерации и невязка снова совпали точно. Полный снимок каждого
REV не сравнивался. Новый editor оставлен открытым на этой сцене и
поставлен на паузу после 0,16 с. Снимок `active-final.png`, показанные
метрики — `energy-edges-native.jsonl`, сравнение — `energy-edges-comparison.json`.
Сборка и тесты завершены до запуска последнего измерения.

Даже бесконтактный шаг остаётся примерно в **780 раз** медленнее
целевых 5 мс; доставка поз и публикация метрик добавляют ещё около
60–90 мс на наблюдавшийся шаг. Последние миллисекунды нужно считать
по `full_worker_*`, а не исключать этот расход из результата. Одна сцена
с малой скоростью проверена; предел на 300–400 тысячах произвольных активных REV
этими измерениями не подтверждён.

## Оставшаяся работа

Существующая строка `collision` включает также учёт свободной неявной
диссипации: её целиком нельзя приписывать поиску столкновений. В диагностику
добавлены отдельные `*_without_*` поля, вычитающие вложенный учёт энергии
из соответствующего этапа; исходные полные поля сохранены.

Подтвердить временную сходимость контакта и допуск 10%: текущие проверки
эквивалентности оптимизации этого не заменяют. Снизить стоимость учёта
энергии и поиска столкновений, затем переносить на GPU именно
проецируемую контактную систему с проверкой истинной невязки. Простое
включение существующего GPU-решателя для контактных связей меняет задачу
и не считается корректной оптимизацией.
